## 1. 戰報風格規範

第三人稱、繁體中文、軍事紀錄口吻，短促克制。戰錘氛圍放在標題、配色及角色識別，不靠杜撰戰果。不可把未命中寫成閃避成功、把掩體攔截寫成裝甲擋下、把倒地寫成陣亡、把失敗寫成永久損失或滅絕令。不得責罵使用者，也不連結現實任務懲罰。

一般單事件展開後最多 80 個 Unicode 字元；射擊彙整最多 140。角色／武器顯示短名最多 16 字，完整名稱保留於詳細資料；超長用精簡固定格式回退，不截斷傷害、結果或事件記錄。畫面允許換行，不用強制單行省略重要資訊。時間由 tick／模擬頻率換算，不能用播放速度推算戰鬥時間。

### 事件對應與佔位符

`hit` 對應 shot/outcome=hit；`cover` 對應 cover；`miss` 對應 miss。`shooter`、`target` 由來源 ID 取得名稱；`weapon` 使用該事件的武器，不讀播放當下的最新裝備。`amount` 取事件記錄傷害，不用武器基礎值重算；若引擎 amount 含溢出傷害，保持同一統計口徑，不宣稱它等於實際扣除 HP。

`burst` 是多次射擊紀錄的呈現彙整，不代表新增連射技能。建議最多 2 秒窗口，只合併同射手、同目標、同武器且未被關鍵事件切開的紀錄。保留全部 sourceEventIds；shots = hits + coverHits + misses，amount = 原始事件 amount 加總。只有一次射擊不合併。命中 0 次也必須如實顯示。遇到倒地、換槍、換彈、取消、結算必須結清窗口；時間標記為起訖時間，依原始事件次序呈現，不重複計分。

`swapSecondaryEngaged` 只能在「因貼身而切副武器，且換裝完成」時使用；`swapPrimary` 同樣只用於完成事件。開始切換可直接用中性文案「{shooter}開始切換武器」，不可提前更新當前武器。取消則「{shooter}的動作中止」，無完成效果。未確認原因的副武器切換用「{shooter}已切換為{weapon}」，不得臆測敵人貼身。

`reload` 只對應完成換彈；進行中、中斷、倒地取消都不能套用。`down` 不推定永久死亡、不附帶招募損失。三種結果句型只根據模擬終局判定，不能因播放器播完、UI 計時到點自行判勝負。超時保持 timeout，不改成失敗。

目前非 shot 事件部分資訊只在 text 中。請 Claude 用事件的結構化欄位或產生當下快照補足 weapon／actionPhase／reason；不要靠中文字串正則猜原因，也不要用最後一格狀態回填歷史。這是呈現資料契約補充，不改模擬規則。若暫時拿不到原因，使用中性文案。

句型選擇使用事件 ID 與模板版本的固定雜湊，或固定輪替；不可消耗戰鬥 RNG，重播不得改戰果。關鍵事件不合併、不隱藏。一般射擊可收折，原始紀錄必須可展開追溯。

## 2. 立繪裁切與使用

JSON 座標採原圖像素、左上原點，x/y/width/height；不先去透明邊、不翻轉、不重新縮放再套座標。24 張均讀取實際尺寸並檢查範圍。頭像 360×360；上身框一般 800×800，雙人重武器組 1000×800 保留組員關係，不能強制拉伸成正方形。

建置產出頭像 128×128、上身最長邊 480 的 WebP；保持比例，採 contain。第一階段優先產生 cadian-* 與 traitor-guardsman，但「有圖」不代表解鎖這些兵種或裝備。雙人組頭像是主射手，不代表第二名個體也有獨立肖像。阿斯塔特圖是未指定戰團的舊基準，擴充前另審，不直接當正式戰團角色。

這是固定身分肖像，不是動態裝備展示。立繪原本畫上的槍不會因換裝消失，所以畫面須另列「目前武器」圖卡，並標示立繪為角色示意；切槍時更新武器卡與文字，不宣稱肖像上的槍已更換。禁止把另一把武器直接疊到持槍立繪上。

注意：24 張中沒有一般卡迪安步槍兵，不能拿持鏈鋸劍的中士冒充。一般步槍兵可沿用 cadian-kit 的 standing.png 作完整立繪 contain 備援，頭像未另驗收前不強套中士裁切。半身框偏上身識別而非完整武器展示，長槍槍管可能超出框外；武器辨識以独立裝備卡為準。

## 3. 裝備圖確認

第一階段確認沿用 cadian-kit 的 lasgun.png、laspistol.png、armor.png（雷射步槍、雷射手槍、防破片甲），精確相對路徑見 equipment.json。不是新增熱射槍、甲殼甲或動力甲。standing/kneel/sidearm 是人物圖，不列為裝備圖。

原圖不需重畫背景。UI 統一深灰綠底、低對比邊框；contain 顯示並保留約 10% 內距，槍管不能被 cover 裁掉。不把裝備貼圖當人物骨架掛件。裝備相容性、主副槽、護甲值仍以正式系統為準，不能從圖片名稱推定所有人都能裝。

## 4. 關鍵時刻插圖

第一階段不另製插圖，不讓美術成為上線阻塞。

- 倒地：原頭像降彩度＋明確「倒地」徽章，不加墓碑或死亡文案。
- 切副武器：角色頭像＋雷射手槍卡＋完成狀態；開始與完成分開。
- 勝利／失敗：共用結算版面，改標題與狀態色，並列原始戰鬥統計；不虛構佔領／撤退／全滅情節。
- 顏色不能是唯一辨識；徽章需文字。這些效果由 UI 實作，不製作逐格素材。

後續若確定需要收藏式插圖，另開里程碑委託；不先量產每兵種的倒地／勝敗圖。

## 5. 「突擊」詮釋：第一階段有條件沿用

同意沿用現有測試版：只有明確指定突擊的叛軍前進接敵；一般 hold 射手仍維持射擊職責，不因裝步槍就自動衝鋒。這是本作測試命令，不是宣稱官方單位規則，也不等同新增近戰兵種。

依現行 engine，敵我任一方帶 assault 命令、雙方存活、在接敵距離內且有視線，才是近身威脅。保持現有 ENGAGE_RANGE／DISENGAGE_RANGE 判斷，不修改門檻。受牽涉的雙方各自依自己的狀態機切手槍，不是全隊同步換槍，也不是一方完成便假定另一方完成。牆後或普通持槍敵人單純靠近不應被敘述成成功突擊。

手槍沿用較低傷害、射程、彈量與換裝時間；不得暗加刀劍攻擊、衝鋒傷害或近戰加成。遭打斷的換彈不得補滿彈藥；倒地取消動作，不播完成文案。脫離威脅依原狀態機換回步槍。

正式多兵種階段才另設「接近目標的命令」與「近战裝備／攔截能力」兩層資料；本輪不新增此系統、不要求重平衡。既有突擊情境測試勝率不可視為平衡已驗收。

## Claude 接入驗收

1. 同種子／同部署的原始戰果與改版前一致；文案變體不能改 RNG。
2. 每條戰報可追溯來源事件；彙整前後次數、傷害一致且無重複。
3. 測到換裝開始／完成／取消、換彈被打斷、倒地、超時與兩種勝敗；武器卡只在完成時切換。
4. 縮圖不載入 24 張原始大圖，裁切不越界、不拉伸；優先檢查第一階段 9 張角色圖。
5. 測試版保持無正式資源扣除／獎勵；經濟接入由另案規格決定。

本次只完成設計交接與裁切驗證，尚未驗證 Claude 的正式戰報 UI 或執行期縮圖效能。
