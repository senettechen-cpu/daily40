## 規則實作與詮釋（請 GPT／使用者確認）

1. **纏鬥觸發**：主規格規定「只有處於近戰／攔截狀態的敵人在 1.2 格內才算纏鬥，槍手靠近不算」。本階段只有持槍叛軍，因此新增「突擊」命令：只有被情境指定為突擊的叛軍會衝向我方，接觸後雙方切手槍。沒有近戰動畫，突擊兵接觸後以手槍攻擊。這是測試版的詮釋，不是新增兵種。
2. **固定對向戰線**：我方持守命令只在 x≤6（C(3)／C(7) 掩體之後），敵方只在 x≥10；中間第 7–9 列只有突擊兵會進入。任何單位都不會走到對方戰線之後，因此永遠只需要 SE／NW 兩個朝向。
3. **掩體**：實牆完全阻擋視線與射擊；低掩體正面 −25 命中，被掩體擋下的射擊顯示「擊中掩體」。
4. **切槍一致性**：切換期間的畫面依交接包播放過渡視角，但已提交武器、傷害來源與裝備欄要等切換完成的那一刻才改變。死亡時取消進行中的切換，武器不變；被迫切槍會中止換彈，彈量不補。

## 效能紀錄

| 項目 | 結果 |
| --- | --- |
| 模擬一步（12 單位） | 約 0.2–0.25 ms（開發機，瀏覽器內） |
| 完整重繪戰場（React＋DOM，82 張圖、333 個 SVG 節點） | 桌面 1.25 ms；手機視窗模擬 2.0 ms（同一台 24 核桌機，**不是真手機**） |
| 真實手機 | **未量測**：需要使用者以 `--host` 在目標手機上開啟，並回報頁面右下角的 fps 與模擬時間 |

預覽面板在隱藏或背景狀態時會把 requestAnimationFrame 節流到每秒 1–4 幀，所以頁面上的 fps 在那裡不準；開發版提供 `window.__battleBench()` 量測純渲染成本。

## 已知限制與美術缺件（交 GPT）

- **掩體內換彈／切槍**：`reload`、`swap-*` 都是站姿畫面，在掩體後換彈或切槍時人物會站起。需要掩體姿勢版本，或由設計決定先縮回再站起。
- **手槍受擊**：`hit` 只有持步槍的版本；持手槍時被擊中只做小幅位移。
- **敵側掩體**：只有 SE 沙包圖；敵方那一側的掩體也用同一組圖。
- **手機尺寸**：375px 寬時人物約 32px 高，辨識度偏低；可能需要橫向畫面或縮放。
- **平衡**（40 個種子）：標準交火我方勝 16 次；近身突擊 40 勝；以寡擊眾 0 勝。這只是測試數據，數值調整屬 GPT／使用者。
- 單位 ID 以編號區分；叛軍都用同一套外觀。
