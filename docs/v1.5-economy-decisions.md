# v1.5 經濟與技術決策紀錄（2026-09-21）

使用者於 2026-09-21 逐項確認（grill 問答）。本文件優先於 [v1.5 規格](progression-economy-ascension-v1.5.md) 第 2、3 節中相衝突的收入規則；其他 v1.5 規則不變。

## 1. 軍需收入（取代 v1.5 第 2–3 節對應條目）

錢包：v1.5 軍需，新錢包從 0 起算，開局 +40；介面可沿用「榮耀」名稱。舊 glory／rp 轉唯讀「歷史戰功」。

| 來源 | 規則 | 來源鍵 |
| --- | --- | --- |
| 記帳 | 每筆 +20，每使用者每「記錄日」前 3 筆；依記錄當天（使用者時區，預設 Asia/Taipei，伺服器判定），不依支出日期；補登占當天名額 | `ledger:<expenseId>` |
| 今日核心 | 最多 3 個，完成各 +10；可前一天預設；截止 09:00；09:00 後可替換，但數量上限＝09:00 時已勾選數；已完成者不能再勾、已完成核心鎖定 | `core:<YYYY-MM-DD>:<taskId>` |
| 專案 | 不限數量，每案上限 120；需至少 3 子項，手動指定恰好 3 個里程碑各 +20；結案 +60 僅在建立日之後的日子才發（同日建立結案只得里程碑）；里程碑只能換成未完成子項，已發獎者鎖定 | `project:<id>:ms:<subTaskId>`、`project:<id>:close` |

- 取消：每日核帳（+10 與核帳功能都不做）、舊任務 RP／+5 榮耀、連續天數獎勵、專案子項 +50、結案難度×500 與星球倍率、記帳 +50。
- 撤銷：已發獎的記帳刪除／復原、里程碑子項刪除或取消勾選、專案刪除，一律寫沖銷分錄扣回；記帳名額隨之釋放。
- 負餘額：允許暫時為負；為負時不能購買；已購裝備不收回。

## 2. 記帳快速選單

- 手動釘選項目在前，其後為近 30 天最常用品項（即時由紀錄計算）；自動項可一鍵釘選或隱藏。
- 項目存類別、品項、付款方式及選填金額。有金額：一鍵記帳並顯示 5 秒「復原」（復原＝刪除，適用扣回）；無金額：帶入欄位並聚焦金額。日期預設今天。
- 釘選／隱藏存伺服器，跨裝置同步。

## 3. 舊制處理

- 舊 RP、glory、部隊、器官進度、腐化保留並唯讀，舊花費按鈕隱藏；不刪資料。
- 上線前先在正式環境做小修補：停止每分鐘腐化累加、駐軍減員、滅絕令鎖畫面，移除伺服顱骨（會把真實任務標完成）。其他舊制照舊直到新制上線。

## 4. 範圍與架構

- 上線範圍：經濟＋名冊＋軍械庫＋戰鬥一次上線；飛昇另排（待 GPT 器官清單與 v1.5 第 8 節四項使用者決定）。
- 名冊、軍械庫、戰鬥照 v1.5 規格；平衡問題附模擬數據交 GPT／使用者。
- 模組依領域切分：`rewards`、`ledger-rewards`、`daily-core`、`project-rewards`（本期），`roster`、`armory`、`combat`、`ascension`（其後）。規則純函式放根目錄 `shared/`，前後端共用；伺服器為軍需唯一權威，獎勵事件以唯一來源鍵冪等。
- 環境：本機 git（基準提交後開發）；**不安裝測試資料庫套件**，改以記憶體假資料庫測試實際路由，上線前另在真實 PostgreSQL 驗證 SQL 一次；正式環境 Zeabur（GitHub 自動部署＋Zeabur PostgreSQL），推送前必問、上線前先手動備份。
- v1.5 經濟以伺服器環境變數 `V15_ECONOMY=on` 開啟；未開啟時記帳獎勵維持舊制。
