# 軍械庫與星區介面整合 — 2026-09-27

狀態：已修改正式介面元件並通過本機測試，尚未部署。沒有更動價格、傷害、授權、戰役解鎖或獎勵規則。

## 本輪完成

### 軍械庫

- 將資料請求與呈現分開：`Armory.tsx` 負責認證、讀取與操作；`ArmoryPanel.tsx` 可用虛構資料獨立驗收。
- 搜尋、分類、採購目錄／我的庫存、已持有與未配發數量、可採購篩選。
- 武器傷害、命中次數、射程、穿甲與護甲資料直接讀取現有戰鬥定義；相容性沿用共享配發驗證。
- 採購前顯示單件成本與剩餘軍需；回收前確認物品與退款。起始配發裝備不可回收，與伺服器規則一致。
- 清楚列出授權、軍需與配發限制。改裝品明示尚無安裝入口，不以人物配發冒充武器安裝。
- 防止連點重複送出；讀取失敗時保留可重試狀態並停用寫入操作，不把未知餘額顯示成零。
- 寫入已成功但隨後重新載入失敗時，保留成功通知與讀取錯誤，不把它誤報成購買失敗。
- 修正目錄過時說明：甲殼甲是先攻 -1，不是移動速度 ×0.90；電漿槍不以未實作的彈藥機制描述。兩份共享目錄同步。

### 星區戰役

- 接入既有三張世界橫幅與四個據點圖示，放在 `public/battle-assets/sector/campaign/`。
- 顯示世界進度、據點狀態、情報與前置關卡；鎖定據點明列尚未完成的條件。
- 保留既有情報規則：失利或收復後才顯示完整敵方編成。

- 手機採單欄；選取據點後移到情報區並提供焦點，尊重減少動態效果設定。

## 交接：尚未完成的系統缺口

1. **改裝安裝流程**：共享 `assignmentError` 明確拒絕把改裝配發給人物；目前沒有對應的武器安裝入口。本輪只揭露限制，沒有自創安裝規則或資料結構。Claude 應先提出武器實例綁定、拆卸／回收、相容性、重複安裝與改裝等級先決條件，再依既定決策流程實作；介面、API 與戰鬥讀取須一致驗證。
2. **真實帳號驗收**：預備環境驗證購買 → 配發 → 收回 → 回收 → 重登，核對庫存、軍需持久化與使用者隔離。需測試帳號，不使用使用者正式資源試買。
3. **其餘頁面**：每日任務、記帳、名冊與飛昇仍應逐頁驗收；本輪不宣稱全站介面已完成。避開 Claude 同時修改的名冊／戰前情報與規則提案。
4. **正式發布閘門**：仍依 `docs/battle-release-candidate-2026-09-27.md`；本輪未提交、推送或部署。
