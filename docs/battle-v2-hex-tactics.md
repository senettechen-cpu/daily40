# 戰鬥 v2：六角格回合制（技術設計）

2026-09-24。Claude 撰寫技術設計；美術方向與數值基線由 GPT 決定，重大變更由使用者驗收。
本文只提設計，**尚未實作任何一行**。

## 0. 使用者定案

> 「以戰旗格子為戰場移動互動。我可以不用直接操控，但讓角色 —— 我決定好裝備上場後 ——
> 讓角色自行行動攻擊。」

參考作品：Warhammer 40,000: Tacticus（六角格、回合制、五人小隊、傷害類型剋制護甲）。
**差異**：Tacticus 是玩家逐一操控；本作是**自動戰鬥**，玩家的決策在出戰前。

這推翻主規格第 6 節的即時模擬。以下第 2 節列出被取代的東西。

## 1. 設計的第一原則：看得懂

玩家不操控，所以整場戰鬥必須是**可解釋的**。每一次行動，戰報都要能說出
「誰、為什麼、做了什麼、結果如何」。

一個看不懂的自動戰鬥等於一顆亂數按鈕。所以：

- AI 用**明確的評分規則**，不用隱藏權重或機器學習
- 每次啟動在戰報寫一行決策理由
- 玩家的三個出戰前決策（配裝、站位、姿態）都要能在戰報裡看到後果

## 2. 取代了什麼

| 現況 | v2 |
| --- | --- |
| 即時 tick 模擬，20 tick/秒，時限約 24 秒 | 回合制，回合上限 10 |
| 16×10 方形格（`shared/battle/terrain.ts`） | 六角格，建議 11×9 |
| 8 個「通道」決定開場位置 | 部署區內自由擺位 |
| 每 tick 一張快照（484 張） | 每次單位啟動一張快照（約 60 張） |
| 只有雷射槍／雷射手槍有戰鬥數值，其餘 16 件裝備帶上場不生效 | 全部 18 件都有數值 |
| 六個人行為完全相同 | 職責各有被動與主動技能 |

受影響的程式：`shared/battle/sim/engine.ts`（433 行，等於重寫）、`rules.ts`、
`scenarios.ts`、`terrain.ts`；`src/battle/report/report.ts`、`TacticalMap.tsx`、
`BattleStage.tsx`。**不受影響**：軍需經濟、名冊、軍械庫、XP、G1 門檻、嘉獎解鎖、
伺服器裁決架構。

## 3. 戰場模型

**座標**：axial `(q, r)`，六角距離
`dist = (|dq| + |dq+dr| + |dr|) / 2`。放在新模組 `shared/battle/hex/`。

**尺寸**：建議 11 欄 × 9 列（約 99 格）。比現在的 160 格小，因為手機直向要塞得下，
而且回合制的每一格都要有意義。

**部署區**：我方最下兩列、敵方最上兩列。六人可在部署區內任意擺位。

**地形**（每格一種）：

| 地形 | 效果 |
| --- | --- |
| 開闊 | 無 |
| 掩體 | 受遠程攻擊 −25% 傷害；進入需消耗全部移動力 |
| 高地 | 射程 +1、命中 +10%；移動進入消耗 2 |
| 障礙 | 不可進入、阻擋視線 |
| 險地 | 可進入，回合結束受 5 點傷害 |

**視線**：兩格之間畫直線，穿過任何「障礙」即阻斷。掩體不阻斷視線，只減傷。

## 4. 回合結構

```
回合開始
 └ 雙方交替啟動：我方 1 → 敵方 1 → 我方 2 → 敵方 2 → …
    （某方單位用完時，另一方連續啟動剩下的）
 └ 每個單位一回合啟動一次
回合結束：險地結算、技能蓄力 +1、狀態效果遞減
```

**啟動順序**：隊內依「先攻值」由高到低排序，先攻值 = 職責基礎 + 裝備修正，
同值以角色 id 穩定排序（保證可重現）。

**單位一次啟動可做**：
- 移動（0 ~ 移動力 格）**＋** 一個行動（攻擊 / 技能 / 進入掩體）
- 或 衝刺（移動力 ×2，不能行動）
- 或 原地待命（回復少量技能蓄力）

**結束條件**：
- 一方全滅 → 另一方勝
- 第 10 回合結束仍雙方存活 → 超時（沿用現有 `timeout`）

回合上限沿用 Tacticus 的「ROUNDS LEFT」顯示，讓玩家知道拖延會超時。

## 5. 傷害模型（本次的核心借鑑）

現在只有兩把槍有數值，其餘 16 件「帶著但不生效」。v2 用**傷害類型 × 護甲類型**
一次解決，新增武器只要填四個欄位就能上場。

**武器欄位**：`damage`（每次）、`hits`（攻擊次數）、`range`（格）、`damageType`、
`penetration`。

**護甲欄位**：`armour`（數值）、`armourType`。

**結算**：

```
每次命中：
  命中判定  = 基礎命中 + 高地 − 距離懲罰 − 目標掩體
  傷害      = round(damage × 類型係數 × 100 / (100 + max(0, armour − penetration)))
總傷害 = 每次命中結果 × hits
```

類型係數表（**候選值，待 GPT 審**）：

| 傷害類型 ＼ 護甲類型 | 無甲 | 布甲/防破片 | 硬甲/甲殼 | 動力甲 |
| --- | --- | --- | --- | --- |
| 雷射 las | 1.0 | 1.0 | 0.8 | 0.6 |
| 爆彈 bolt | 1.0 | 1.1 | 1.0 | 0.9 |
| 電漿 plasma | 1.0 | 1.2 | 1.4 | 1.5 |
| 火焰 flame | 1.4 | 1.2 | 0.8 | 0.6 |
| 近戰 melee | 1.2 | 1.0 | 0.9 | 0.8 |
| 動力武器 power | 1.0 | 1.2 | 1.3 | 1.4 |

設計意圖：雷射槍是全能但打不穿重甲；電漿是反甲但（見技能）有過熱風險；
火焰清雜兵；動力武器是近戰版的反甲。這讓「換裝備」真的改變打法，
而不只是數字變大。

**18 件裝備的歸類**由 GPT 決定，我只提供欄位。

## 6. 職責：被動與主動

每個職責一個被動（永遠生效）＋ 一個主動（蓄力滿了自動施放）。
自動戰鬥中「何時施放」由 AI 依第 7 節的規則決定。

| 職責 | 被動 | 主動（蓄力回合） |
| --- | --- | --- |
| 中士 sergeant | 相鄰友軍命中 +10% | 全隊本回合移動力 +1（3） |
| 步槍兵 rifleman | 無 | 瞄準射擊：本次攻擊命中 +25%、傷害 ×1.5（2） |
| 神射手 marksman | 射程 +2 | 穿甲射擊：無視目標護甲（3） |
| 醫療 medic | 相鄰友軍回合結束回復 5 | 治療：指定友軍回復 30（3） |
| 工程 engineer | 在掩體格時額外 −10% 傷害 | 佈設掩體：將相鄰一格變成掩體（4） |
| 重武器 heavy | 移動後不可攻擊 | 壓制：範圍攻擊，命中者下回合命中 −20%（3） |

蓄力：每回合 +1，待命 +2，滿了在下一次啟動時自動使用。

## 7. AI：玩家的決策如何變成行為

玩家在出戰前替**每個角色**選一個姿態。姿態是玩家唯一的行為控制項，
所以必須少而分明。

| 姿態 | 行為 |
| --- | --- |
| 固守 | 不離開部署區；優先射擊射程內目標；優先進入掩體 |
| 推進 | 朝最近敵人前進，維持在自己的最佳射程；掩體優先於前進 |
| 側翼 | 繞向敵方側後；接受較長路徑以取得無掩體射線 |
| 護衛 | 跟隨指定友軍（通常是醫療或重武器），保持 2 格內 |

**每次啟動的決策流程**（固定順序，可寫進戰報）：

```
1. 主動技能蓄力滿且條件成立 → 使用，結束
2. 列出所有可射擊目標，評分：
     分數 = 預期傷害 × 擊殺加成(2.0) × 威脅權重 − 暴露懲罰
3. 有可射擊目標 → 依姿態決定是否先移動到更好的格，然後射擊
4. 無目標 → 依姿態移動（推進/側翼/護衛各有不同的目標格評分）
5. 無事可做 → 待命
```

**威脅權重**：醫療 1.5、重武器 1.4、中士 1.3、其餘 1.0。
意圖是讓 AI 會優先打掉治療者，玩家因此有理由把醫療放後排 —— 站位就有意義了。

## 8. 玩家的決策點（因為不操控，這些就是全部的玩法）

1. **六人選誰**（名冊）
2. **每人帶什麼**（軍械庫；傷害類型讓這裡真的有取捨）
3. **部署在哪一格**（部署區內自由擺）
4. **每人的姿態**（第 7 節四選一）

出戰後不再介入。戰報必須讓這四個決定的後果看得出來。

## 9. 伺服器裁決與重播（不變）

現有架構完全保留：伺服器擲種子、自跑模擬、自寫 XP，客戶端只重播。
回合制讓這件事更輕：

- 快照從每 tick 一張（484）降到每次啟動一張（約 60）
- 戰報敘述從「逐秒事件」改成「逐次行動」，更好讀

**相容性問題**：`operations` 表已存的舊場次是 v1 的種子與格式，v2 引擎重播會壞。
處理方式：`operations` 加一欄 `engine`（`v1` / `v2`），舊場次標記為 v1 並**不再提供重播**，
只留結果紀錄。不做資料轉換 —— 兩套模擬本來就不可能得出同一場戰鬥。

## 10. 分階段實作

| 階段 | 內容 | 可驗收的東西 |
| --- | --- | --- |
| P0 | `shared/battle/hex/`：座標、距離、鄰接、視線、路徑（A*） | 單元測試 |
| P1 | 回合制引擎：啟動順序、移動、射擊、勝負、回合上限 | 六人 vs 六人能跑完並得出結果 |
| P2 | 傷害類型 × 護甲表；18 件裝備全部有數值 | 換裝備會改變結果 |
| P3 | 姿態與 AI 評分 | 同一組人換姿態會有不同打法 |
| P4 | 被動與主動技能 | 職責之間有差異 |
| P5 | 戰報改寫（逐次行動敘述）＋ 六角戰術圖 | 看得懂為什麼輸贏 |
| P6 | 美術與動畫接入（GPT 素材） | 畫面 |

P0–P2 是骨架，做完就能取代現有模擬；P3–P4 是讓它好玩；P5 是讓它看得懂；
P6 是讓它好看。建議照順序，每階段可獨立驗收。

## 11. 需要 GPT 的

**數值**：
- 傷害類型係數表（第 5 節是候選值）
- 18 件裝備各自的 `damage` / `hits` / `range` / `damageType` / `penetration`
- 三種護甲的 `armourType`
- 六個職責的先攻值與移動力基礎值
- 技能的蓄力回合數與效果強度

**美術**（另開需求單）：
- 六角地形貼圖：開闊、掩體、高地、障礙、險地
- 單位棋子：現有 8 名角色立繪要能俯視化，或另出棋子圖
- 行動特效：射擊、命中、未命中、倒地、治療、技能
- UI：回合計數、啟動順序條、血條、姿態圖示

## 12. 待決

1. **敵人怎麼來？** 目前三個情境的敵人是寫死的。v2 是否需要敵方也有職責／裝備／姿態？
   建議需要，否則剋制關係只有單向。
2. **倒地 = 死亡？** 現在是「倒地但不造成永久傷亡」。配合已上線的「敗戰負傷當日禁賽」，
   建議 v2 維持不永久死亡，倒地只影響該場。
3. **部署擺位的 UI** 在手機上怎麼做（拖曳 vs 點選格子）。
4. **是否保留舊模擬**作為回退。建議不保留，兩套會一起腐爛。
