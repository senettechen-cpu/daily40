## 3. 引擎前置工作（動畫的依據）

動畫必須由模擬事件驅動，但現有原型引擎缺少以下狀態，這些是主規格已定的規則，屬 Claude 的實作範圍：

| 規格（主規格） | 原型現況 | 需補 |
| --- | --- | --- |
| 主→副 0.45 秒、副→主 0.65 秒，期間不可攻擊，顯示切換進度（主規格〈切換耗時〉及手持狀態條款） | 僅把冷卻設為 3／4 tick（0.3／0.4 秒），沒有「切換中」狀態 | `weaponSwap: { to, startTick, endTick }` |
| 步槍首次瞄準 0.35 秒，換目標／移動後才重瞄（主規格武器節奏條款） | 無瞄準狀態 | `aimUntil` |
| 彈匣與換彈 2 秒、手槍獨立彈量、被迫切換取消換彈（主規格〈與換彈的關係〉） | 無彈量 | `ammo`、`reloadUntil` |
| 掩體姿態 | 只有 `tactic === 'covered'` 一個布林 | 事件：入掩體、探身、回掩體（由位置到位觸發） |

這些改動會讓戰鬥節奏改變，屬戰鬥模組（上線範圍 E 階段），會與 v1.5 武器表（雷射 16 傷、12 發）一起做並附平衡模擬，不在本回覆中實作。

## 4. 素材介面提案（請 GPT／使用者確認後再量產）

### 選型：序列幀＋獨立武器層（不採骨架動畫）

生成式素材難以穩定拆出骨架部件；序列幀最能保留繪製品質。武器維持獨立圖層，才能讓同一動作套用不同已裝備武器，避免「換槍就要重畫整套人物」。

### 角色圖層（由後到前）

1. 背負層：收起的主武器／槍套內手槍（依實際裝備切換圖）
2. 遠側肢體
3. 身體（不含手持武器）
4. 手持武器：每款武器一張獨立圖，依每幀握點掛上
5. 近側手／手指（覆蓋槍身的部分）

接地陰影由程式繪製，不需交付。

### 格式

| 項目 | 提案 |
| --- | --- |
| 單幀畫布 | **192×192** RGBA（交接候選為 256×256，見下方記憶體估算） |
| 人物站姿高度 | 約 120px；蹲姿用同一尺度 |
| 地面錨點 | 每幀固定於 (96, 176) |
| 方向 | 四個等角對角方向 NE／NW／SE／SW，各自繪製，不鏡像 |
| 交付 | 每個「陣營 × 動作 × 方向」一張橫向條圖 PNG，檔名 `{陣營}-{動作}-{方向}.png`，另附同名 `.json` |
| 幀數與時間 | 採交接第 7 節幀數；播放時由程式把幀平均拉伸到規格時間（如切槍 450／650ms），美術不需配合毫秒 |

### 每幀錨點 JSON（格子內像素座標）

```json
{ "cell": 192, "anchor": [96, 176],
  "frames": [{ "ground": [96,176], "shoulder": [..], "triggerHand": [..], "supportHand": [..],
               "holster": [..], "sling": [..], "hitPoint": [..], "weaponAngle": 0 }] }
```

武器圖另附 `grip`（對應 triggerHand）與 `muzzle` 兩個錨點；槍口特效一律從 `muzzle` 發出，不再使用猜測值。

### 掩體分層

每個掩體段交付兩張同畫布、同錨點的圖：`back`（後側面＋頂緣）與 `front`（近側遮擋面），另附 JSON：地面中心、保護方向、站位點、越頂射擊點、側探射擊點、足跡多邊形。渲染時 `back` 排在角色之前、`front` 依其近側邊緣深度排序，角色繞到前方時自然在前。

### 記憶體估算（需要使用者／GPT 取捨）

交接第 7 節每方向約 59 幀 × 4 方向 × 2 陣營 = 472 幀。解碼後：

| 畫布 | 未裁切 | 裁切透明邊後（估計 ~45%） |
| --- | --- | --- |
| 256×256 | 約 124 MB | 約 56 MB |
| 192×192 | 約 70 MB | 約 31 MB |

這是手機 PWA，124 MB 的圖片記憶體風險過高。建議 192 畫布＋自動裁切打包＋WebP，並只載入當場出戰的陣營。

## 5. 驗收截圖計畫（對應交接第 8 節）

會做一個開發用預覽頁，固定亂數種子、可暫停到指定 tick，截圖用瀏覽器實拍；每張另以 DOM 的 `data-*` 屬性（手持武器、切換進度、姿態）自動斷言，避免只憑肉眼。

1. v2 基準與新實作同縮放疊圖：C／W／B 與部署點一致（已有座標測試）
2. 同一士兵站→蹲：頭盔、槍長、靴子尺寸不變、腳底錨點不漂移
3. 正面有效掩體／側翼失效／完全遮擋三張
4. 角色在掩體前、後各一張
5. 主→副、副→主各四段暫停（起始／中間／結束／就位）：UI、手持、背帶、事件一致
6. 近失／沙包命中／人物命中
7. 1×／2×／暫停／低動態
8. 六人同時交戰（需等名冊模組完成，屬後續整合驗收）

## 6. 缺件清單

- **美術（GPT）**：卡迪安與叛變守軍的正式分層序列幀（四方向、交接第 7 節全部動作）；每款武器獨立圖＋握點／槍口；沙包 `back`／`front` 分層與 JSON；W 工業箱正式圖。
- **設計確認（使用者／GPT）**：§4 的 192 畫布與序列幀選型；是否接受四方向全部各自繪製的工作量。
- **引擎（Claude）**：§3 的切換、瞄準、彈量、掩體姿態事件。
- 目前分鏡板（cover-pose-board-r2）只作姿勢與材質溝通，不擷取任何座標；其 02 格比例偏小、08 格手槍仍有鷹徽，GPT 已註明。
