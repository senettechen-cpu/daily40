## 四、堅守這件事值得單獨看

使用者回報「指定堅守的士兵真的完全不動，而且雙方距離太遠根本打不到」。挖開來是**三件事湊在一起**：

1. `hold` 分支對部署區外的格子回 `-Infinity` —— 是「拒絕」不是「不建議」。
2. **所有戰場的兩個部署區都是全空曠地**，所以同一段程式裡 `sheltered ? 10 : 0` 的掩蔽加分
   **永遠不會觸發**。寫了意圖，但在地圖上是死碼。最近的掩蔽在部署區外 1 格，而步兵一回合走 3 格。
3. 兩個部署區最近距離 **6 格**，雷射槍射程 **5**。開場誰都打不到誰。

| 情境（堅守） | 改前 | 改後 |
| --- | ---: | ---: |
| w1-n2 補給港 | 41%（發呆 63%） | **80%**（發呆 10%） |
| w2-n1 冶煉區 | 4%（發呆 17%） | **52%**（發呆 12%） |
| w2-n2 兵工廠 | 0%（發呆 81%） | **28%**（發呆 8%） |

整體 55 格（11 關 × 5 套裝備）平均 **+0.6 個百分點** —— 敵方也拿到對稱護牆，互相抵銷。

**兩個要記住的結果**：

- **w2-n2 的堅守（28%）現在高於推進（13%）。** 這是主規格第 18 節要求的
  「同一關不同配置有不同決策」第一次在數據上成立。
- **「護牆減成 1 格能放過新手隊」被實測推翻**：fresh 隊平均從 −1.7 惡化到 −2.5，
  w2-n2 的堅守也崩回 5%。護牆愈少，對**人數少**的一方愈有利，而我方是六人隊。已記錄，別再試。

**實作陷阱**（寫在 `engine.ts` 註解裡）：第一版把「不得離開部署區」寫成對所有格子生效，
結果部署區**外**的單位每回合被拉回、下回合再走出來，來回震盪。
拒絕只對「當下站在部署區內」的單位生效才正確。

## 五、這次修掉的三個靜默錯誤

都是「測試是綠的，但東西是壞的」。

### 1. 排序拿沒補零的地區日期字串比大小

```
today = "2026/9/30"        ← 9 月，沒補零
day   = "2026/10/22"
"2026/10/22" < "2026/9/30" → true   （'1' 排在 '9' 前面）
```

**所有 10–12 月的到期日都被判成「早就逾期」排到最頂**，比真正逾期的還前面。
改用 `dayKey()`（補零 ISO）。原本那句 `|| due < 今天00:00` 是對的，但被壞掉的比較短路掉了。

能活這麼久是因為**儀表板排序完全沒有測試**。已補 `tests/task-slate-order.test.cjs`
（渲染元件、讀 markup 裡的順序）。

### 2. 假資料庫沒有模擬 jsonb

`tasks` 的 `due_times`／`slots_done`／`month_days` 在真實 schema 是 **jsonb**，但
`tests/helpers/fake-db.cjs` 把 UPDATE 寫進去的值當**純字串**存。經過一次 PUT 之後，
這些欄位讀回來是 `'["08:00"]'`，所有讀陣列的規則都靜默看成「沒有時段」。
舊程式在那條路徑剛好也回 0，所以測試一直是綠的。

### 3. 兩個測試借用 `hold` 當「別動」

轟擊測試用 `stance: 'hold'` 來固定位置，而不是表達姿態語意。堅守一改它們就壞。
改用 `movement: 0`，那才是它們真正的意思。

**接手須知**：這三個都是同一類錯誤 —— 測試斷言的東西剛好跟壞掉的行為一致。
看到「這個明明該有差卻量到 0」的時候，先懷疑量測。

## 六、量測工具（與 09-29 相同，新增一支探針模式）

| 指令 | 用途 |
| --- | --- |
| `node scripts/sim-battles.cjs <關卡> <隊伍> <場數>` | 勝率、回合數、每場倒下人數。`FORMAT=json`、`GEAR="c2=shotgun"` |
| `node scripts/sim-value.cjs [場數] [隊伍]` | 裝備價值矩陣。**基準隊伍必須不擁有任何受測裝備** |
| `TASKS=<n> node scripts/sim-pacing.cjs 300` | 節奏模型。`tasks` 是每天幾筆軍需收入（多時段任務現在是一個時段一筆） |
| `node scripts/sim-crates.cjs` | 補給箱機率 |

**姿態的量測沒有現成腳本**：`sim-battles.cjs` 用 `placementsFor(..., undefined)` 取預設姿態
（射手推進、醫療堅守）。這次是另外寫了一支一次性探針，把六人全部指定同一個姿態，
並統計「無可射擊目標，原地待命」佔全部行動的比例。要再量姿態的話，
那個比例是比勝率更早、更靈敏的訊號 —— 它直接說明「這個姿態有沒有在做事」。

## 九、已知限制

- **新手隊在世界 1 前段變難**：敵方槍手現在開場就站在護牆後（受擊 ×0.75），而 fresh 隊沒甲可以還手。
  `close-assault` −18、`w1-n1` −16、`w1-n2` −17。裝備起來（flak 以上）差距消失。
  **減少護牆數量不是解法**（第四節）；要放鬆得從敵人配置或起始配發著手。
- **倒下的代價對裝備不足的隊伍很重**：flak 隊在世界 2、3 每場平均倒 5.4–5.9 人（滿編 6）。使用者知情。
- **軍需收入沒有上限，而且現在更高**：新增一個八時段任務就是每天 +80。使用者知情並選擇如此。
- **伺服器採信前端時間**（`routes/tasks.ts`）：前端控制 `lastCompletedAt` 就控制了獎勵日期。
  多時段改動之後，單一時段的請求也走這條路（以 `slotsDone` 觸發）。單人自用影響低。
- **一個月選多天的月任務語意不一致**：新增視窗的 1–31 方格可以複選，但 `deadlineDay` 取最小值當截止日、
  `isSettled` 判定「完成一次就整月結清」，而 `occursOn`／`monthDayLabel` 是按「多次發生」寫的。
  選了 10、25 號的話，10 號做完就消失到下個月，25 號那次不會出現。**使用者尚未裁示要哪一種語意。**
- 精準組與阿斯塔特組專長仍無實測數據。
- 戰報只存在 API 回應與瀏覽器分頁暫存，關掉分頁可能遺失。
- 改裝品（功能改裝、整備一階／二階）**沒有安裝入口**。
- `outputs/` 與 `tango-trip/` 是無關的日本行程檔案，躺在 repo 根目錄未追蹤。
- 火焰／電漿／通訊三個職務**在戰鬥引擎裡沒有任何專屬行為**（搜尋 `duty === 'flamer'` 等一次都沒出現），
  先攻與專長組跟步槍兵相同，卻沒有步槍兵的主動技能，而且貴 40 軍需。尚未提案。
- `heavy` 職務**招募不到也不在起始六人裡**，但重武器三條規則只對 `heavy` 生效 ——
  步槍兵扛重武器反而滿射速、不用副手、移動照打。大概不是設計意圖。尚未提案。
